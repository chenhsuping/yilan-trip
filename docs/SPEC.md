## 1. 產品概述

將一份宜蘭 2 天 1 夜的親子行程，從單張圖片升級為「會動、可互動、隨時間更新」的網頁。
目標使用者為參加此趟旅行的家庭成員（10 位大人、5 位兒童），用途為：行前瀏覽、行中導航、費用分攤查詢、以及分享給群組。

**設計語彙**：宜蘭在地元素（溫泉、三星蔥、雞）＋親子可愛風；暖色系配色、圓角、漸層、輕動畫。

## 4. 功能規格

### 4.1 分頁切換（Tabs）
- 四個分頁：**DAY 1** / **DAY 2** / **住房指南**（見 4.10）/ **入住須知**（見 4.11）。
- 切換時觸發煙火動畫（DAY 1 暖色、DAY 2 冷色、住房指南紫色、入住須知金綠色，由 `TAB_HUE` 定義）。
- 分頁列 sticky 固定於頂端。
- 後兩個分頁不是行程日，切過去時自動隱藏「💰 費用試算」區塊、「回程結語」與「📍 目前行程」浮動鈕（`INFO_TABS` 陣列判定）。浮動鈕見 4.12。

### 4.2 時間軸（Timeline）
- 垂直時間軸，左側為序號圓點（依類型配色），右側為行程卡片。
- 卡片捲動進入視窗時淡入（IntersectionObserver，門檻 0.15）。

### 4.3 地圖導航
- 每個地點的地址為連結，點擊於新分頁開啟 Google Maps 搜尋。
- 連結格式：`https://www.google.com/maps/search/?api=1&query=<地點名稱+地址>`（URL 編碼）。

### 4.4 費用試算（Calculator）

**1.4 版起改為固定報名名單，不再是「大人／兒童」兩顆計數器。** 早期版本讓使用者用 +/− 調整人數，但那沒辦法表達「這個小孩幾歲」，因此算不出免睡殿 6 歲以下免費這件事——實測用預設的 10 大 5 小算出 NT$65,700，但依實際報名成員的年齡重算是 NT$65,100，差了 600 元（2 位 6 歲以下的孩子在免睡殿與萌萌森林都該免票，卻被當一般兒童收費）。既然報名成員是已知、固定的名單，計算機直接列出真實家庭與年齡，不用再讓人手動調整湊數字。

**資料結構**：`ROSTER` 常數，一個家庭一筆：

```js
{fam:'雅茹一家', people:[{},{},{age:11},{age:7}]}
```

`people` 是成員陣列；沒有 `age` 欄位的視為一般付費大人（非長者），有 `age` 的依年齡判定票種。要調整報名人數或年齡，改這個陣列就好，畫面與金額全部自動重算。

**⚠️ 假設待確認**：萌萌森林物語官方只公告「全票／兒童票 6–12 歲」，**沒有說明 6 歲以下怎麼收費**。目前程式比照免睡殿的規則、假設 6 歲以下免票；若現場其實仍收兒童票，5 歲、3 歲這兩位會各多 150 元，總金額增加 300 元（NT$65,100 → NT$65,400）。這個假設寫在計算機下方的 `.note` 文字裡提醒使用者出發前跟現場確認，程式碼裡也有對應註解——若確認收費方式不同，改 `pForest()` 裡 `age<6` 那個分支即可。

**分攤規則**（1.4 版起，門票與共用費用分開處理）：

| 類別 | 項目 | 誰付 |
|------|------|------|
| **共用費用** | 白色城堡包棟、代烤燒肉 | **只由大人均分**，兒童不分攤 |
| **門票** | 免睡殿、萌萌森林 | **現場統一付款**（一次結清），但金額**按各家人數與年齡分攤** |

早期版本把門票也算進均分池，等於讓沒帶小孩的家庭補貼別家的兒童票。包棟與代烤是全團共用、跟人數無關的固定成本，均分合理；門票則是人數愈多付愈多，各家人口結構不同，混在一起分會失真。

**「統一付款」與「各家分攤」是兩件事**：兩個景點在現場都是由一個人一次付清，但那只是付款方式；帳仍然按各家自己的人數與年齡算。介面文字寫「統一付款 · 各家依人數分攤」就是要把這兩件事講清楚，避免被讀成「大家均分」。

- 每位大人均分額 = `ceil((包棟＋代烤) ÷ 大人數)` = `ceil(60,200 ÷ 10)` = **NT$6,020**（無條件進位，確保收足）。
- 每家應付 = `該家大人數 × 6,020` ＋ `該家門票小計`。
- 大人數由 `pIsAdultPayer()` 動態算出（沒填年齡，或年齡 >12），目前 10 人。

**版面**（兩段式，對應「先看景點、再看各家」）：

1. **`#breakdown` — 各項費用**：四行景點小計，每行第二排用小字標示分攤方式（`.by-adult` 青色「大人均分」／`.by-fam` 金色「統一付款 · 各家依人數分攤 · …」）。免睡殿與萌萌森林會標出付費人數（例如「13／15 人 × 150」），一眼看出有幾位免票。下方接總計與 `.perhead` 均分額。
2. **`#famList` — 各家應付**：每家一行（`.fam-row`），左邊家庭名＋組成小字（「2大＋11歲、7歲」），右邊該家總額＋拆解小字（「均分 NT$12,040 ＋ 門票 NT$1,400」）。

### 4.5 依現在時間定位行程
- 以訪客**裝置本地時間**判斷目前進度。
- 行程時間表（供程式判斷，`[時,分]`）：
  - DAY 1（2026-08-29）：11:30 / 13:30 / 15:00 / 18:00
  - DAY 2（2026-08-30）：11:00 / 11:30 / 12:30 / 14:20
- **提前 30 分鐘跳站**（`LEAD_MS`）：**當前這站結束前 30 分鐘**就把「目前行程」跳到下一站，讓大家在上一站還沒結束前就看到接下來要去哪、有時間收拾移動。判斷用的是 `f.at`（生效時間）而非 `f.t`（表定開始時間）。

  **結束時間從 `trip` 的 `time` 字串解析**（`endHM()`）：`"11:30–13:00"` → 13:00；`"15:00 起"`、`"11:00"` 這種沒有結束時間的，退回用**自己的開始時間**往前推 30 分鐘。不另外維護一份結束時間表，避免改行程時漏改。

  **每站至少保有 10 分鐘「進行中」**（`MIN_SHOW_MS`）：奕順軒是 11:30–12:00、只有 30 分鐘，結束前 30 分鐘正好等於它的開始時間，不擋的話它會在生效當下就被下一站蓋過、從頭到尾不會顯示進行中。退房（11:00，無結束時間）也是同樣情形。

  各站實際生效時間：

  | 站別 | 表定 | 跳到這站 | 依據 |
  |---|---|---|---|
  | D1 大仁哥桶仔雞 | 11:30–13:00 | 11:00 | 首站，自己的開始 −30 |
  | D1 宜蘭免睡殿 | 13:30–14:30 | **12:30** | 大仁哥 13:00 結束 −30 |
  | D1 白色城堡 | 15:00 起 | 14:00 | 免睡殿 14:30 結束 −30 |
  | D1 代烤燒肉 | 18:00 起 | 17:30 | 白色城堡無結束時間 → 自己 −30 |
  | D2 退房 | 11:00 | 10:30 | 代烤無結束時間 → 自己 −30 |
  | D2 奕順軒 | 11:30–12:00 | **11:10** | 退房無結束時間 → 自己 −30 = 11:00，被 10 分鐘下限推到 11:10 |
  | D2 萌萌森林 | 12:30–14:00 | **11:40** | 奕順軒 12:00 結束 −30 = 11:30，被 10 分鐘下限推到 11:40 |
  | D2 莫內咖啡 | 14:20 起 | 13:30 | 萌萌森林 14:00 結束 −30 |

- 四種狀態：
  - **出發前**：標記第一站，徽章顯示「還有 N 天出發」；出發當天但還沒到第一站**生效時間**則顯示「今天出發」。
    天數以**日曆日**（兩邊午夜時間點）相減，不是拿時間差直接除以 24 小時 —— 早期版本用 `Math.ceil((first.t-now)/DAY_MS)`，出發當天只要還沒到第一站時間（哪怕只差 5 分鐘）都會被無條件進位成「還有 1 天」，跟行程根本沒有隔一天矛盾。
  - **即將前往**（已提前跳過來、還沒到表定時間）：徽章「⏳ 即將前往」。與進行中同樣會自動捲動——提前跳站的用意就是要讓人看到。
  - **旅程中**（已過表定時間）：切到當天、捲動至當下站、卡片高亮＋「🔴 進行中」徽章。
  - **結束後**（末站起 +3 小時，以**表定**時間計）：標記末站「✅ 行程結束」。
- 右下「📍 目前行程」浮動按鈕（見 4.12）：任何時候點擊都跳到當下該站。
- 每 60 秒自動更新徽章位置（不強制切頁／捲動，避免干擾閱讀）。

**全部動畫遵守 `prefers-reduced-motion`，使用者關閉動態時停用。**

### 4.9 出遊兩天天氣預報（蓋版視窗）

行前與行中掌握天氣用。**1.3 版起本視窗只做天氣**：原本的 NCDR 各國颱風路徑動畫（1.1／1.2 版的 4.9）已整段移除，相關常數、影片與靜態圖降級邏輯一併刪除。

**觸發方式**
- 右下浮動鈕 **🌤️ 天氣預報**（見 4.12），常駐可點。
- **自動開啟有期限**：只在 `Date.now() < WX_AUTO_END` 時延遲 900ms 自動彈出一次；`WX_AUTO_END` = 出發當天（`dayDates[0]`）**台灣時間 09:30**，程式碼寫成 `Date.UTC(Y, M, D, 1, 30, 0)`（台灣 09:30 = UTC 01:30）。過了這個時間點就只能手動開 —— 行程已經開始，蓋版視窗只會擋路。
- 關閉後不再自動彈出，重新載入頁面才會依上述條件再判斷一次。

| 逐時欄位 | `weather_code`、`temperature_2m`、`precipitation_probability` |
| 時區 | `Asia/Taipei` |

每日與逐時**在同一支請求內取回**，不多打一次 API。

**為何不用中央氣象署開放資料**：CWA API 需要申請金鑰，本站是公開靜態頁，金鑰無處可藏，因此改用免金鑰的 Open-Meteo。

**日期來源**：起訖日期由第 4.5 節的 `dayDates` 推導（`wxISO()` 負責把 0-based 月份 +1），**不另外寫死一份**，改行程日期時天氣與自動彈出期限會一起跟著變。

**上半部：兩天摘要（並排按鈕）**
- 兩張 **`<button class="wx-card">`** 並排（`.wx-grid` 固定兩欄，**手機也維持並排**，只縮小內距與字級），各顯示 emoji 圖示、中文天氣描述、高／低溫（四捨五入至整數）、最高降雨機率，底部一行「🕐 看逐時預報」。
- `WMO` 常數負責 weather code 對應圖示與中文；未知 code 退回 `🌡️` 與破折號，不會顯示 `undefined`。
- **摘要的天氣 code 由逐時自行推算（`wxDayCode()`），不直接用 `daily.weather_code`**：API 的每日值取「當日最嚴重」，一小時的極端值就會綁架整天的門面 —— 實測 2026-08-29 只有 17:00 是 code 96（雷雨夾冰雹）、全天雨量僅 6mm，卡片卻整天掛著冰雹，而宜蘭 8 月下冰雹實務上不會發生（數值模式對 96/99 的已知誤判）。改成只採「當日至少出現 2 小時」的 code，孤例不算數，取其中最嚴重者；全部落空才退回 API 的每日值。
- **降雨機率標「最高」二字**：`precipitation_probability_max` 是當日單一小時的最高值，不是整天下雨的機率。不標的話「100%」會被讀成整天都在下雨（實測 8/29 早上 09–12 時只有 11–59%、雨量 0mm，尖峰落在午後雷陣雨時段）。
- 選取狀態以 `aria-selected` 表示（珊瑚色外框 + 光暈），並帶 `role="tab"`／`role="tablist"`。
- 卡片下方顯示距出發天數，並標注「一週外的預報僅供參考，越接近出發越準」；出發當日起改為「預報會隨時間修正，出發前建議再看一次」。

**下半部：逐時預報表**
- 點任一天的按鈕，下方 `#tyHours` 列出該日逐時：時間 / 圖示 / 天氣描述 / 溫度 / 降雨機率（`.hr-row` 為 5 欄 grid，`.hr-list` 最高 44vh 可捲）。
- **選到的是今天時，已經過去的時段不列**（`isToday && hh < nowH` 直接跳過），標題改為「接下來的天氣」。行程進行中往回看幾點下過雨沒有意義，清單也不必再捲。未來的日子仍列滿 24 小時；**已經過去的日子維持完整列出**，切回去不會變成空白。
- **底色標記**：綠底 = 當天行程時段，紅底 = 現在這個小時（僅當該日就是今天）。
- 行程時段由 4.5 的 `startTimes` 推算（`wxTripHours()`：第一站開始時 ～ 最後一站開始時 +2 小時），**不另外寫死**，改行程時間時會自動跟著調整。
- 開啟時自動把清單捲到「現在」或「行程開始」那一列，不必自己找。
- 預設選取「今天」（`d.time.indexOf(wxTodayISO())`），出遊當天開頁就直接看到今天；不在行程兩天內則預設 DAY 1。

**時區處理**：所有「現在」的判斷都用 `Date.now() + 8 小時` 位移後以 UTC getter 讀出（`wxNowTW()`／`wxTodayISO()`），訪客不論在哪個時區結果都一致。

**降級**：抓不到（HTTP 錯誤、離線、回傳空陣列、`null`）時顯示「目前取不到天氣預報」訊息與重試提示，不留白。成功後於同一次瀏覽階段快取（`wxDone`），不重複請求；失敗則下次開啟會重試。

**互動與無障礙**：ESC／點遮罩／✕ 三種關閉方式；開啟時鎖背景捲動、焦點移至關閉鈕並做 Tab focus trap，關閉時焦點還給觸發元素；`aria-hidden` 同步切換。與 4.10 的住房指南視窗**共用同一組鍵盤處理**（`MASKS` 陣列查出目前開著的是哪一個）。

**約束例外**：本區塊是全站唯一的外部相依，破壞了第 2 節「無外部相依、可離線開啟」的原則 —— 即時資料本質上無法離線。影響侷限於此視窗；行程、地圖連結、費用試算、住房指南在離線時皆照常運作。

### 4.12 右下浮動按鈕（FAB）

三顆常駐按鈕，由下往上堆疊：

| 按鈕 | id | 配色 | 行為 |
|------|-----|------|------|
| 📍 目前行程 | `#nowBtn` | 珊瑚→蜜金 | 跳到當下該站（見 4.5） |
| 🌤️ 天氣預報 | `#tyBtn` | 青→紫 | 開啟天氣蓋版（見 4.9）；emoji 有輕晃動畫 |
| 💰 費用試算 | `#calcBtn` | 蜜金→蔥綠 | 捲到費用試算區塊（見 4.4） |

**堆疊方式**：外層 `.fabs` 是 `position:fixed` 的 flex 容器（`flex-direction:column-reverse`），按鈕本身只有 `.fab` 樣式、不各自定位。**1.4 版起改用這個做法**——早期三顆各自寫死 `bottom:18px/76px/134px`，隱藏其中一顆時（切到住房指南／入住須知會隱藏「目前行程」）原位會留下一個洞，其餘按鈕不會遞補。改成 flex 之後隱藏的按鈕自動收合，也讓之後要加第四顆時不必重算每一顆的座標。

`.fabs` 設 `pointer-events:none`、`.fab` 設 `pointer-events:auto`，避免容器的空白區域擋住底下內容的點擊。

**`#calcBtn` 的分頁處理**：費用試算區塊只掛在行程日分頁下，若使用者正停在住房指南／入住須知，按鈕會**先切回 DAY 1** 再捲動，否則按了會沒反應。捲動時預留 90px 給 sticky 分頁列。
